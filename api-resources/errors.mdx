Every error is a JSON body with the same shape, whatever `Accept` header you send. The HTTP status tells you the kind of problem; the `code` tells you the exact case; the `message` is written to be shown to the customer.

## The error response

```json
{
  "code": "40012",
  "message": "OTP is invalid or expired."
}
```

| Field                 | Present         | Description                                                                                                                                                                                                      |
|-----------------------|-----------------|------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------|
| `code`                | Always          | A string of five digits. The first three are the HTTP status, the last two tell apart the cases that share a status: `40012` is the twelfth kind of `400`. Branch on this, never on `message`.                    |
| `message`             | Always          | What went wrong, in words a customer can read. Sent in English, or in Arabic when the request carries `Accept-Language: ar`. Messages an insurance provider wrote are passed on as received. Wording may change, so never match on it. |
| `details`             | `42201` only    | Field validation errors: each key is the field, each value a list of messages for it.                                                                                                                             |
| `retry_after_seconds` | `429` only      | How long to wait before trying again. The same value is in the `Retry-After` header.                                                                                                                             |

A `2xx` response never carries a `code`, and `204` responses have no body at all.

## Handling errors

1. **Branch on the HTTP status first.** `4xx` means the request has to change before it can succeed; `5xx` means it did not reach the insurer and can be retried as it is.
2. **Then on `code` for the cases you treat differently.** Every case has its own code, so you can send the customer back to exactly the step that needs fixing: `40012` to the OTP field, `40003` to the owner id and birthdate, `40013` to the IBAN, `42205` to the employee name that matched nobody.
3. **Show `message` for `400` and `422`.** It says what the customer has to fix, and it is already localized for `Accept-Language: ar`.
4. **Retry `5xx` and `429` with a back-off, never a `4xx` unchanged.** The same `400` will come back until the input changes.

```javascript
const res = await fetch(url, { method: "POST", headers, body });
if (res.ok) return res.json();

const error = await res.json();
switch (error.code) {
  case "40012": return askForOtpAgain(error.message);
  case "40001": return requestOtpFirst();
  case "42902": return showCountdown(error.retry_after_seconds);
  case "42201": return showFieldErrors(error.details);
  case "40101": return refreshTokenAndRetryOnce();
  default:
    if (res.status >= 500 || res.status === 429) return retryLater(error.retry_after_seconds);
    return showToCustomer(error.message);
}
```

## HTTP status codes

| Status | Meaning               | When                                                                                                     |
|--------|-----------------------|----------------------------------------------------------------------------------------------------------|
| 400    | Bad Request           | The insurer or Yasmina rejected the request as sent: a wrong OTP, an unverifiable car or owner, a quote that no longer exists, a policy that is already cancelled. |
| 401    | Unauthorized          | No valid token, or wrong client credentials on `/oauth/token`.                                            |
| 403    | Forbidden             | The token is valid but the product is not enabled on your account.                                        |
| 404    | Not Found             | The record in the URL does not exist or does not belong to you, or there is no such endpoint.             |
| 405    | Method Not Allowed    | Wrong HTTP method for the endpoint.                                                                       |
| 422    | Unprocessable Entity  | Field validation failed, or the record is not in a state that allows the request yet.                    |
| 429    | Too Many Requests     | Rate limited. See [Rate limiting](/api-resources/rate).                                                   |
| 500    | Internal Server Error | Something failed on Yasmina's side, including an insurer that timed out.                                  |
| 504    | Gateway Timeout       | An insurer could not be reached at all.                                                                   |

## Error codes

| Code    | Status | Meaning                                                                                                                                       | What to do                                                                                          |
|---------|--------|-----------------------------------------------------------------------------------------------------------------------------------------------|-----------------------------------------------------------------------------------------------------|
| `40000` | 400    | Rejected for a reason that has no code of its own yet. `message` says what.                                                                    | Show the message.                                                                                   |
| `40001` | 400    | No OTP was requested for this phone number before this step: the quote OTP before requesting quotes, the issue OTP before issuing the policy. | Request the OTP, let the customer enter it, then repeat the step.                                   |
| `40002` | 400    | The car could not be verified against the national vehicle registry (Yakeen).                                                                 | Check the sequence or customs number and the model year with the customer, then retry.             |
| `40003` | 400    | The owner could not be verified against the national identity registry (Yakeen).                                                              | Check the owner id and birthdate with the customer, then retry.                                     |
| `40004` | 400    | The registry check failed without saying whether the car or the owner was the problem.                                                        | Check both, then retry.                                                                             |
| `40005` | 400    | The mobile number is not registered to this owner id.                                                                                          | Ask for the mobile number registered in the owner's name.                                           |
| `40006` | 400    | The mobile number is already tied to a different National ID or Iqama.                                                                         | Ask for another mobile number, or the id it belongs to.                                             |
| `40007` | 400    | `quote_request_id` belongs to another client or no longer exists.                                                                              | Check the id: only the client that created a quote request can use it.                              |
| `40008` | 400    | `quote_reference_id` is not one of this quote request's quotes.                                                                                | Send a reference from the quotes you were given.                                                    |
| `40009` | 400    | `quote_price_id` is not one of the prices of that quote (motor) or of that quote request (medical).                                            | Send a price id from the quotes you were given.                                                     |
| `40010` | 400    | The policy is already cancelled, or a cancellation is already pending.                                                                         | Nothing: treat the policy as cancelled.                                                             |
| `40011` | 400    | A `benefits` entry is not offered on that quote.                                                                                               | Send only benefit ids listed on the quote.                                                          |
| `40012` | 400    | The OTP is missing, wrong, or expired.                                                                                                         | Let the customer enter it again, or request a new one.                                             |
| `40013` | 400    | The insurer could not accept the IBAN: it is not valid or is not the owner's.                                                                  | Ask for the owner's own Saudi IBAN.                                                                 |
| `40014` | 400    | Vehicle photos were sent for a TPL price; they are only needed, and only accepted, for comprehensive cover.                                    | Skip the photos step for TPL.                                                                       |
| `40015` | 400    | The insurer refused the vehicle photos. `message` says why, for example an image it could not read.                                            | Let the customer retake the photo named and upload again.                                           |
| `40016` | 400    | The insurer refused the request, in its own words: it would not quote this vehicle, could not register a customs-number vehicle, or could not create the payment link (for example because the quote expired). | Show the message. Usually the customer has to start again from quotes.        |
| `40017` | 400    | The insurer has not issued the policy document yet, so there is nothing to cancel against.                                                     | Retry once the policy is issued.                                                                    |
| `40018` | 400    | The identity and passport documents for this travel quote were already uploaded.                                                               | Nothing: carry on to purchase.                                                                      |
| `40019` | 400    | No address matches the short address.                                                                                                          | Check the short address with the customer.                                                          |
| `40101` | 401    | Not authenticated: no `Authorization` header, an expired or revoked token, a token sent without the `Bearer` scheme, wrong client credentials on `/oauth/token`, or an expired embed session. | Request a new token and retry once. If that also fails, check the credentials. |
| `40301` | 403    | Authenticated, but this product is not enabled on your account, or the account is not approved yet.                                            | Contact Yasmina to enable the product.                                                              |
| `40401` | 404    | The record whose id is in the URL does not exist or belongs to another client. Also returned when an embed session is used for a different quote request than it was created for. | Check the id. Ids are only visible to the client that created the record.  |
| `40402` | 404    | No such endpoint.                                                                                                                              | Check the URL against the API reference.                                                            |
| `40501` | 405    | The endpoint exists but not for this HTTP method.                                                                                              | Check the method against the API reference.                                                         |
| `42201` | 422    | Field validation failed. `details` lists every failing field with its messages; `message` is the first of them.                                | Fix the fields listed in `details`.                                                                 |
| `42202` | 422    | The company has no employees yet, so there is nothing to price.                                                                                | Set the company's employees first.                                                                  |
| `42203` | 422    | The request is well-formed but the record is not in a state that allows it, for a reason that has no code of its own yet. `message` says what. | Show the message and do the step it names first.                                                    |
| `42204` | 422    | The insurer has already issued this policy, so its declarations can no longer be changed.                                                      | Nothing to declare: the policy is live. Changes need a new policy.                                  |
| `42205` | 422    | An `ids_or_emails` entry names nobody on the policy. `message` lists the entries.                                                              | Use the `nationality_id`, `iqama_id` or email exactly as set on the employees.                      |
| `42901` | 429    | Rate limited. `retry_after_seconds` says for how long.                                                                                         | Wait for `retry_after_seconds`, then retry.                                                         |
| `42902` | 429    | An OTP was requested for this phone number less than three minutes ago on this endpoint.                                                        | Show a countdown from `retry_after_seconds`; the OTP already sent stays valid meanwhile.            |
| `50001` | 500    | Something failed on Yasmina's side. This includes an insurer that did not answer in time.                                                      | Retry after a short back-off. If it keeps failing, contact support with the time and the endpoint.  |
| `50401` | 504    | An insurer could not be reached.                                                                                                               | Retry after a short back-off.                                                                       |

Codes not in this list are not returned by the current API. If you see one, treat it by its HTTP status.

## Errors along the customer journey

The tables below list what each step of an integration can return beyond the errors every endpoint shares: `40101` (bad token), `40301` (product not enabled), `40402` (wrong URL), `40501` (wrong method), `42901` (rate limited) and `50001` (server error).

Payment needs no call of its own, so it has no errors of its own: read the policy, and `pending_declarations` names who still has to declare while `payment_link` appears once nobody does. A failed or abandoned payment is never an API error either: the customer pays on a hosted page, and the policy simply stays unissued (`status` 0, `provider_policy_id` null) until a payment succeeds. The [webhooks](/webhooks/guide) tell you when it is issued.
